To make it an agent, a developer would need to add tool access, permissions, repeated decisions and safe stopping rules.

THE SAME WORKFLOW AS ED · OPEN MODEL · ZERO GPU COST

From your computer to your own public chatbot

The project uses one real-model English-only Gradio app. Follow the steps to clone the whole project, then publish.

From installing Python to a public Digital Twin

A simple course, one step at a time. Choose your computer, then follow the commands in order.

01

Open PowerShell

Search for PowerShell from the Windows Start menu.

02

Install Git

Check whether Git is installed. If missing, install it with winget, then reopen PowerShell. If winget is unavailable, use the Git for Windows link below.

git --version
winget install --id Git.Git -e
Git for Windows
03

Install uv

uv manages Python and the app dependencies. Reopen PowerShell after installation. If winget is unavailable, use the official uv install guide linked below.

winget install --id astral-sh.uv -e
uv --version
uv install guide
04

Install Python 3.12

uv installs Python for the project. You do not need to replace your system Python.

uv python install 3.12
uv python find 3.12
05

Clone the full project

Clone the full AI Learning Lab repository. If you already cloned it, skip this step and use your existing folder.

git clone https://github.com/ayubabuzer/ai-learning-lab.git
06

Open the Digital Twin folder

From the cloned project, enter the Lesson 06 Gradio app folder. Run both commands below only after cloning. If you already have the project, navigate to your existing folder instead.

cd ai-learning-lab
cd lessons/06-digital-twin/gradio-app
07

Personalise your knowledge file

Edit about-me.txt and save a fictional profile. Do not publish private information.

notepad about-me.txt
08

Try the chatbot locally (optional)

Optional: this installs the full AI model and dependencies and may require significant memory and several gigabytes of downloads. Learners without a suitable machine should skip local inference and deploy the Space instead.

uv run python app.py
09

Create and verify your Hugging Face account

Sign up and confirm your email. For free ZeroGPU Spaces, your personal account must be eligible and older than 30 days.

Create accountZeroGPU requirements
10

Sign in safely from the terminal

Before running login: open Access tokens, create a token with Write permissions, and copy it privately. Then run the login command below and paste the token when prompted. Never put the token in the project or public files.

uvx hf auth login
uvx hf auth whoami
Access tokens
11

Publish with our safe script

From the Gradio project folder, run the same deployment command used in the course. Our deployment script requests ZeroGPU (zero-a10g) automatically when creating the Space. You do not need to select hardware in a terminal prompt.

Optional check before publishing: uv run deploy.py --check validates the files without contacting Hugging Face.

uv run deploy.py
What our deployment script will ask:
  1. Choose a Space name — Enter a simple name such as my-ai-digital-twin, or press Enter for the suggested name.
  2. The script selects the five app files, requests free zero-a10g hardware for eligible accounts, and prints your Space URL. No Git credential, GitHub Action or app-file selection prompts are part of this command.

Before deployment: Create a Hugging Face Write token at the linked page, log in using uvx hf auth login, and verify with uvx hf auth whoami. Keep your token private.

Safe upload: deploy.py stages only five source files. Your local .venv, model downloads, and Git history are never uploaded. A large-folder warning belongs to the older gradio deploy workflow, not our recommended script.

⚠️ The script requests zero-a10g automatically, not cpu-basic. Free hosting requires an eligible account; queues and limits apply. The deploy tool may not offer hardware selection in every version—verify it on Hugging Face.

12

Test your public link and share it

Open and run the deployed app: At the end of a successful deploy, open the Space URL shown in the terminal (typically https://huggingface.co/spaces/YOUR_USERNAME/YOUR_SPACE). If you missed it, sign in to Hugging Face → profile → Spaces → choose your Space. Click the App tab. If it says Building or Starting, view the build/runtime logs and return when the app is Running. Type an English question about the fictional character in the chat box and press Enter/Send. Try a question the profile does not answer as well. Hugging Face runs the deployed app: you do not need to keep uv run python app.py running locally. If it sleeps, queues for GPU or shows an error, reload the Space and inspect Logs and Settings → Hardware. Share your link only after confirming the chat works.

📖 Safe one-command deployment📖 نشر آمن بأمر واحد

Run uv run deploy.py inside gradio-app. The script uploads only app.py, twin_core.py, about-me.txt, requirements.txt and a generated Space README. It never uploads .venv, local tokens, caches or Git history. First authenticate using uvx hf auth login with a Write token. On first run, choose a Space name. Future runs update the same Space. After upload, open the printed URL and wait for the App to be Running; check Logs and hardware if needed. If an older Space already contains thousands of tracked files, choose a fresh Space name for a clean deployment.شغّل uv run deploy.py داخل مجلد gradio-app. يرفع السكربت ملفات التطبيق المطلوبة فقط، ولا يرفع .venv أو الرموز السرية أو الذاكرة المؤقتة أو سجل Git. سجّل الدخول أولاً باستخدام uvx hf auth login ورمز بصلاحية كتابة. في أول تشغيل اختر اسم مساحة؛ وفي التشغيل التالي تُحدّث المساحة نفسها. افتح الرابط المطبوع وانتظر تشغيل التطبيق، وراجع السجلات والعتاد إذا لزم. إذا احتوت مساحة قديمة آلاف الملفات المتتبعة، اختر اسماً جديداً لمساحة نظيفة.
